# 特殊能力目錄（Q-P4-6 用）

主流程常碰到「工具不能直接點」的能力。訪談時用 Q-P4-6 讓使用者勾選，**每個勾到的能力都要在提案中寫出做法、模組、風險**，不可默默略過。
沒列在這裡的能力：照同樣格式（觸發 → 做法優先序 → 平台限制 → 模組 → 風險）補一條並寫 ADR。

| # | 能力 | 做法優先序 | 平台 / 工具限制 | 模組 | 風險 / 備註 |
|---|---|---|---|---|---|
| 1 | **Feature flag / 遠端設定**（UI 依 flag 變） | ①測試用戶 / 裝置 targeting 固定 flag ②launch argument / 測試版本地覆寫 ③SDK 的測試資料源（離線 flag 檔）| 遠端 flag 有快取延遲，啟動前要確認已套用 | M2 `config/flags/<profile>.json` + runner `FLAGS=` 維度；flow 用 `requires_flags:*` tag 篩選；狀態檔 / 基線 / 報表帶 profile | 組合爆炸：只挑「上線中 + 即將上線」組合，其餘夜間抽樣 |
| 2 | **無障礙（a11y）自動檢查** | ①框架內建稽核（Flutter `meetsGuideline`：labeled tap target / text contrast / tap target size；Android ATF / Espresso `AccessibilityChecks`；iOS XCUITest `performAccessibilityAudit`，Xcode 15+）②UI 流程中掃 hierarchy：每個可點元素有 label、尺寸 ≥ 48dp/44pt ③字型縮放 × 最小螢幕矩陣 | Maestro 只能做 ② ③；① 要在 App repo 的測試裡做 | **M19** | 結果獨立一區，不混進功能 PASS；先列「違規清單」再逐步設成門檻 |
| 3 | **網路情境**（弱網、離線、斷線重連、離線同步衝突） | ①Android emulator `-netspeed` / `-netdelay`、`adb emu network speed/delay` ②代理注入延遲 / 斷線（toxiproxy、mitmproxy，見 M8）③實機切網路：Android 10+ `adb shell svc wifi disable` / `svc data disable`；8～9 非 root 實機多半無法用指令切飛航模式（`settings put` 不生效）→ 用代理或模擬器 ④飛航模式（Maestro `setAirplaneMode` 只支援 Android 模擬器 / 部分實機）⑤iOS：Network Link Conditioner（影響整台 Mac，要序列化）⑥雲端農場的 network profile；iOS 實機沒有斷網指令 → 用代理 / 農場 profile / 測試版離線開關；**離線同步衝突**：離線改資料時用 API bot（#22）同時改同一筆，恢復網路後以後端狀態斷言衝突處理結果 | 雲端農場多半有網路 profile 參數 | M8 變體；flow 加 `network` tag | 不進 merge gate；結束一定要還原網路（trap / finally）；離線下載前檢查裝置剩餘空間，下載完成用檔案或後端狀態輪詢（設上限） |
| 4 | **即時通訊 / 視訊 / 雙方互動**（WebRTC、聊天、多人） | ①另一方用 bot：後端 test API 讓對方加入，或 headless Chrome `--use-fake-device-for-media-stream --use-file-for-fake-video-capture=<合成影片>` ②兩台裝置各跑一支 flow，用後端狀態同步 ③模擬器 fake camera / mic | iOS Simulator 沒有真相機；視訊畫面只能是合成內容 | M7（對方 bot、session 狀態 API）、M18（兩台裝置） | 斷言用「UI 連線指標 + 後端 session 狀態」雙重確認；截圖不得含真人 |
| 5 | **相機 / 證件拍照 / 掃碼** | ①測試版注入圖片或改走相簿選檔 ②Android emulator 虛擬相機場景 / 自訂影像 ③KYC / 掃碼廠商 SDK 的 sandbox 模式直接回結果 ④雲端農場的相機影像注入（部分農場支援把圖片 / QR 餵給相機，需 spike） | iOS Simulator 無相機 → 只能 ① ③ | M12（推送合成證件 / QR 圖）、M7 | 只用合成證件；廠商 sandbox 要跟廠商確認 |
| 6 | **Email magic link / 驗證信** | ①自架或指定區域的測試信箱（Mailpit / MailHog / 測試信箱 API）取信 → 解析連結 → `openLink` / `adb shell am start -d <url>` / `xcrun simctl openurl` ②後端 test API 直接產 token | App Links / Universal Links 在模擬器要先驗證能開回 App | M7 | 連結一次性：重試要重新寄；寄信有延遲，輪詢設上限 |
| 7 | **OTP（SMS）** | 見 `interview-pipeline.md` Q-P4-4 b 優先序 | | M7 | |
| 8 | **TOTP / 硬體 token** | seed 放機密庫，測試內計算或呼叫 token 模擬 API；處理時鐘偏移、一碼一次 | | M7、M2 Vault | |
| 9 | **生物辨識** | 實機走 PIN fallback / 測試 flag；模擬器用工具的 biometric 指令 | 實機無法自動化 | M5 | 生物辨識本身列模擬器驗證或人工項 |
| 10 | **推播通知** | ①後端 API 驗狀態 ②開通知欄點擊 ③deep link 模擬 | 需 FCM / APNs sandbox | M7 | 見 `appium-pitfalls.md` #12 |
| 11 | **付款 / 第三方頁** | 交易終點要驗 → 金流 sandbox（測試卡、3DS challenge）+ API 查訂單；只是外連 → 驗「已跳轉」 | 外部 App 錢包未必安裝；**非同步付款**（QR / 轉帳類，例如即時付款 QR）：用 PSP sandbox 的「模擬付款」API 代替掃碼付款 → App 輪詢完成頁（有上限）+ 後端訂單狀態斷言 | M7、M6 `gone_text` | 正式環境不跑 |
| 12 | **檔案上傳 / 下載 / PDF 檢視** | 上傳：預先推送測試檔 + 授權；下載 / PDF：驗檔案存在（`adb shell ls`、`simctl get_app_container`）或後端產生紀錄，PDF 內容用後端 API 驗 | 系統選檔器 UI 依 OS 版本不同 | M12、M7 | 選檔步驟多重備援並記錄裝置型號 |
| 13 | **定位 / 地圖 / 路線移動** | 靜態座標：模擬器 `adb emu geo fix`、`xcrun simctl location set`、Maestro `setLocation`、Appium `set_location`。**路線**：①逐點 `set_location` + 間隔（或 Maestro `travel`、Android emulator GPX/KML、`simctl location start` 路徑）②實機：mock location provider（開發者選項指定 mock app，例如 Appium Settings）+ 逐點注入 ③**對方角色位置用後端 API 注入**（最穩，見 #22）。背景定位：Android 10+ `ACCESS_BACKGROUND_LOCATION`、電池最佳化白名單、iOS「永遠允許」需安裝時授權 | 雲端農場多半只能設靜態座標（例如 AWS Device Farm 在 run 層設定經緯度）；地圖 canvas 內元素不可點 → 用 API / deep link 選點 | M12、M7 | 位置資料可能屬敏感個資（Q-P5-3） |
| 14 | **藍牙 / NFC / IoT 裝置配對與控制**（智慧家電、穿戴、車機配對） | **分三層**：①**雲端協定裝置模擬器**（韌體 / 後端提供，講同一套雲端協定）當對方角色 bot（#22）：控制、狀態同步、觸發告警推播 → 不需硬體、可進 CI ②**真機 lab 層**：App × 實際硬體的配對、配網、OTA（M18 受測硬體池：獨佔鎖、健康檢查、每輪前重置到可配對狀態——解綁 API、恢復出廠指令、智慧插座斷電重開）③硬體本身（韌體、電氣）由韌體團隊自測，不在本架構。配網時手機會切到裝置 SoftAP / 失去網際網路，期間的雲端斷言要等切回後再做 | iOS 模擬器**沒有藍牙** → 配對必須 iPhone 實機；Android 模擬器的藍牙支援極有限；藍牙、Local Network、加入 Wi-Fi 的系統對話框在實機只能走 UI（不在 App hierarchy，需 spike） | M7、M18、M6 | **不要**把配對 / 配網整段排除：它通常是第一條主流程；真機 lab 層進夜間、不進 merge gate |
| 15 | **離線 / 背景 / App 被殺後恢復** | `stopApp` / `launchApp`、`adb shell am kill`、背景化（Home 鍵）後回來；離線同 #3 | | M5 | 驗資料一致性用 API |
| 16 | **權限對話框** | 安裝時授權（`adb install -g`、`autoGrantPermissions`、`simctl privacy grant`——**只適用 iOS 模擬器**；iPhone 實機的藍牙 / Local Network / 定位等對話框只能走 UI 或 `autoAcceptAlerts`）；要測對話框本身時才走 UI | 系統 UI 不在 App hierarchy | M12 | |
| 17 | **App 內購買 / 訂閱**（Google Play Billing、StoreKit） | ①開發提供 billing mock / 測試 flag（多數流程用這個）②實機 + license tester 帳號 + 測試卡（核准 / 拒絕），測真正的購買畫面 ③後端訂閱狀態 API 當最終斷言 | **前提**：Android 受測包 applicationId 與簽章要跟 Play 上架版一致、經 internal testing track 安裝（sideload 的 debug 包買不了）；裝置要登入 license tester Google 帳號（雲端農場裝置通常做不到）；購買畫面是 `com.android.vending` 原生 UI（WebView 工具看不到，要切 native）；iOS 用 sandbox 帳號 / StoreKit configuration（模擬器） | M7、M2（tester 帳號） | 訂閱要清理（取消 / 退款 / 用 license testing 的短週期）帳號才能重用；標高風險 |
| 18 | **平板 / 摺疊 / 橫豎屏 / 分割畫面** | runner `FORM_FACTOR=tablet`；定位器 override 層；flow 依 form factor 分支；旋轉用工具指令 | | M3、M10（基線 key 帶 form factor） | 導航結構不同時，分支寫在變體片段，不寫在主流程 |
| 19 | **深色模式 / 主題 / 字型縮放** | 裝置設定切換（`adb shell cmd uimode night yes`、`simctl ui appearance dark`、font scale） | | M10 基線 key 加主題 | |
| 20 | **時間相關**（倒數、時段限制、跨日） | 測試環境可調時間的 API / 測試 flag；不要改裝置系統時間（影響憑證） | | M7 | 視覺回歸要忽略倒數區塊 |
| 21 | **穿戴裝置 / Widget / 車用等延伸介面** | 通常不在本架構範圍，列為「另立專案」並記錄 | | — | 提案寫明排除 |
| 22 | **多 App / 多角色互動**（顧客 + 服務提供者、申請 + 審核） | ①對方角色用後端測試 API 當 bot（接單、更新狀態、推送位置）②兩台裝置各跑一支 flow，以後端狀態為同步點（每個同步點有逾時）③同裝置裝兩支 App 輪流切換（非即時互動才用）| 雲端農場跨裝置同步困難 → 優先 ① | M7、M18、M2（多個 app_id） | 報表 / 狀態檔帶 role；兩端都要截圖當證據 |
| 23 | **遊戲引擎 / canvas UI**（Unity、Cocos、WebGL、自繪地圖） | ⓪**原生自繪 view**（座位圖、圖表、自訂控制項）：請開發用 Android `ExploreByTouchHelper` / iOS `UIAccessibilityElement`（`accessibilityElements`）把每個可點區塊露成虛擬 a11y 節點並給 id —— 自動化可直接定位，也順便改善無障礙（最佳解）①測試 flag / deep link 跳過該模組，結果（例如獎勵）由後端 API 發放並驗證 ②測試版嵌入引擎專用自動化 SDK（Unity：AltTester 等，提供物件層級定位）③影像比對（Appium images plugin、OpenCV template matching）+ 百分比座標，列為最後手段 ④Firebase Test Lab Game Loop 只做穩定性 / 崩潰測試 | 無 accessibility tree，一般 UI 工具看不到內部元素 | M6、M7、M10 | 解析度、低階機掉幀會讓影像比對不穩；跟遊戲團隊確認 SDK 能否進測試版 |
| 24 | **影音播放**（ExoPlayer、AVPlayer、串流） | ①App 測試 hook / analytics 事件確認播放開始、進度、結束 ②`adb shell dumpsys media_session` 看 PlaybackState=PLAYING 且 position 遞增 ③兩次取樣比較進度條 / 時間文字 | 畫面內容不要做像素比對（視覺回歸忽略播放區） | M7、M10 | 離線播放搭配 #3；DRM 內容在模擬器可能無法播放 |
| 25 | **企業 SSO / OAuth（Okta、Azure AD、SAML，系統瀏覽器）** | ①測試 IdP org + 測試帳號，MFA 免除或改 TOTP（#8）②非登入主題的流程用測試 token / deep link 直接帶 session（bypass），**只保留 1～2 條走真實 SSO** ③每個品牌 / 客戶的 IdP 設定放品牌設定檔 | iOS ASWebAuthenticationSession 會先跳系統同意對話框（XCUITest 用 springboard / interruption monitor，Appium 用 `autoAcceptAlerts` 或 springboard）；Android Chrome Custom Tabs 屬於 Chrome 這支 App（Espresso 碰不到 → UiAutomator / Appium native context），雲端裝置的 Chrome 有首次啟動畫面要先處理 | M7、M2、M5 | MFA、IdP 政策改變會讓所有流程一起壞 → 真實 SSO 那條獨立 tag |
| 26 | **MDM 受管 App 設定**（managed app config 推 server URL、tenant） | ①測試版提供覆寫（launch argument / debug 設定頁）②iOS 模擬器：`xcrun simctl spawn <udid> defaults write <bundle> com.apple.configuration.managed -dict ...` ③Android：TestDPC 設 app restrictions（實機 / 模擬器）| 雲端農場裝置通常不能裝 DPC / 設 MDM → 用 ① | M2、M12 | 正式環境行為（真 MDM）只能在少數受管裝置人工驗；**kiosk / lock task / 專用裝置**：測試機改用「測試用 MDM profile」（允許 USB 偵錯、允許安裝測試 driver APK——Maestro driver、Appium Settings / UiAutomator2 server），否則工具裝不上；lock task 會影響 `launchApp` / `stopApp` / 回 Home，kiosk 行為本身另列 1～2 條驗證 |
| 27 | **手寫簽名 / 自訂手勢 / 繪圖** | W3C pointer actions（Appium）、`swipe` 多段路徑（Maestro）、`XCUICoordinate.press(forDuration:thenDragTo:)`、Compose `performTouchInput`；斷言用「簽名已存在 / 送出鈕可用 / 後端收到影像」 | 不做像素比對（筆跡每次不同） | M5、M7 | |
| 28 | **長時間流程**（韌體 OTA、大檔同步、批次處理，數分鐘以上） | 專用的受測硬體 / 帳號；可重複（例如可降版的測試韌體）；進度用後端 / 裝置狀態 API 輪詢，不靠盯畫面；helper `timeout_ms` 依實測放大，runner `MAESTRO_TIMEOUT_MIN` 與 CI job 上限同步調整 | 手機螢幕休眠、App 被切背景 → 保持亮屏設定 | M7、M18 | 排除在 smoke 外，獨立 tag 夜間跑 |

| 30 | **硬體掃描器 / 周邊送 intent**（專用手持機內建雷射掃描、DataWedge 類 broadcast、藍牙掃描槍、刷卡機） | ①測試版提供注入入口（debug broadcast receiver、deep link → `openLink`、隱藏輸入框）②主機端送 `adb shell am broadcast -a <action> --es <data_key> <合成條碼>`：Appium 用 `mobile: shell`（server 需 `--relaxed-security`）或 UiAutomator2 的 broadcast 指令；**Maestro flow 內不能執行 adb 指令**（`runScript` 只有 http）→ 選 Maestro 必須先有 ①，或在主機端做 bridge（flow 透過 http 呼叫本機小服務代送 adb）③keyboard-wedge 模式（掃描器當鍵盤輸入）→ `inputText` ④實體掃描只在少數 lab 裝置或人工驗 | 相機路線（#5）對雷射 / 硬體掃描器無效，不要套用 | M12、M5、P5.5 | 是第一條主流程時，**工具選型前**就要確認注入方式（寫 ADR）；條碼一律用合成資料 |

| 32 | **App Clip / Instant App / 小程式入口**（掃碼或 NFC 直接開輕量版） | iOS App Clip：獨立 bundle id 與 UI test target；模擬器用 `_XCAppClipURL` 環境變數（或 Local Experiences 設定）帶入啟動 URL，Clip 的 .app 要另外安裝；Android Instant App：`adb shell am start -a VIEW -d <url>` + Play Instant 開發工具；驗「輕量版完成 → 引導安裝 / 轉主 App」的交接 | 實機上由系統掃碼 / NFC 觸發的入口只能人工或 spike | M2（多個 app_id）、M5 | 輕量版有大小與 API 限制，定位器另列一份 |
